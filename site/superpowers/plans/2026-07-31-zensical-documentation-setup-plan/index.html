Zensical Documentation Setup Implementation Plan¶

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Set up a local Zensical documentation site alongside the existing Astro-based portfolio site for contributor documentation, following the structure outlined in issue #2 but without automated deployment.

Architecture: We will create a /docs directory at the repository root containing Markdown files organized into sections (Getting Started, User Guide, API Reference, Contributing). Zensical will be installed locally to serve these docs via zensical serve. No changes to the existing Astro site or GitHub Actions workflow will be made.

Tech Stack: - Zensical (static site generator for documentation) - Markdown files for content - Python/pip or uv for Zensical installation - Existing GitHub repository structure

Global Constraints¶

  • Must not modify existing GitHub Actions workflow (.github/workflows/deploy.yml)
  • Documentation must be locally viewable but not automatically deployed
  • Must follow existing project structure conventions
  • All new files must be placed in /docs directory at repo root
  • README.md updates only to add documentation section

## Documentation

This project includes contributor documentation powered by [Zensical](https://github.com/zensical/zensical) in the `/docs/` directory. The documentation is not automatically deployed but can be viewed locally for development and contribution purposes.

### Viewing Documentation Locally

To preview the documentation:

1. **Install Zensical** (choose one method):
   ```bash
   # Using pip and virtualenv
   python3 -m venv .venv
   source .venv/bin/activate
   pip install zensical

   # OR using uv (faster alternative)
   uv init
   uv add --dev zensical
   ```

2. **Start the preview server**:
   ```bash
   zensical serve
   ```

3. **View in browser**: Open <http://localhost:8000> to see the documentation

### Documentation Structure

The documentation is organized into the following sections:
- **Getting Started** - Introduction to the project
- **User Guide** - How to use and customize the project
- **API Reference** - Technical reference (if applicable)
- **Contributing** - Guidelines for contributing to the project

### Documentation Development

- Edit Markdown files directly in the `/docs/` directory and subdirectories
- Changes are automatically reflected when using `zensical serve` (with live reload)
- The `docs/assets/` directory can be used for storing images and other static assets
- Generated site files (in `docs/site/` by default) are ignored by Git to avoid committing build artifacts
