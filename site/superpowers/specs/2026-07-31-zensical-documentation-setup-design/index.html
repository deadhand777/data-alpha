Zensical Documentation Setup Design¶

Context¶

The repository currently lacks comprehensive, centralized documentation. As the project grows, onboarding new contributors and helping users find setup guides, API reference docs, and usage examples becomes difficult. Developers must dig through raw Markdown files across directories or search through closed issues to find answers.

Issue #2 requests setting up a modern, hosted documentation site using Zensical, with documentation site setup, content architecture, automated deployment, and search & navigation.

Goals¶

  • Set up Zensical locally to author documentation in Markdown.
  • Organize documentation into clear sections: Getting Started, User Guide, API Reference, Contributing.
  • Provide instructions in the README for rendering the documentation locally.
  • Do not deploy the documentation site automatically; keep it as a local reference only (per user request).
  • Leverage Zensical's built-in search and navigation for a good developer experience.

Approach¶

We will add a /docs directory at the repository root containing the Zensical documentation source. The site will not be integrated into the existing Astro site nor deployed via GitHub Actions. Instead, we will update the README to explain how to install Zensical and preview the documentation locally.

Why Separate Docs Site?¶

  • Keeps documentation authoring simple with Zensical's conventions.
  • Avoids coupling documentation build with the main site's Astro build process.
  • Allows documentation to be worked on independently.

Why Not Deploy?¶

Per user feedback during design, the documentation will be set up locally only, with instructions in the README for anyone who wants to run it. This reduces complexity and avoids potential conflicts with the existing GitHub Pages deployment.

Content Structure¶

docs/
├── getting-started/
│   ├── index.md          # Overview, prerequisites, quick start
│   ├── installation.md   # Detailed install guides (pip, uv, conda, Docker)
│   └── tutorial.md       # Step‑by‑step first‑time setup
├── user-guide/
│   ├── index.md          # Navigation, styling, customization
│   ├── authoring.md      # Writing Markdown/MDX, using components (migrated from content-guidelines.md)
│   ├── configuration.md  # zensical.toml explained
│   └── recipes.md        # Common patterns (tabs, alerts, code blocks)
├── api-reference/
│   ├── index.md          # Placeholder for generated API docs (if any)
│   └── zensical-cli.md   # Reference for `zensical` commands (new, serve, build)
└── contributing/
    ├── index.md          # How to contribute, workflow
    ├── style-guide.md    # Markdown style, tone, formatting
    └── code-of-conduct.md# Link or copy of project’s conduct

Migration of Existing Content¶

  • docs/content-guidelines.md will be moved to docs/user-guide/authoring.md and adapted to include Zensical‑specific authoring tips (though Zensical uses plain Markdown, we can note how to structure content, use headers, etc.).
  • The README will retain the project overview and gain a new “Documentation” section pointing to the local docs setup.

Implementation Steps¶

  1. Install Zensical locally (documented in README):
  2. Using pip: python3 -m venv .venv && source .venv/bin/activate && pip install zensical
  3. Or using uv: uv init && uv add --dev zensical && uv run zensical
  4. Create the directory structure as shown above under /docs.
  5. Create placeholder Markdown files with minimal content (title, brief description, TODO comments) to ensure the site builds.
  6. Migrate docs/content-guidelines.md to docs/user-guide/authoring.md.
  7. Optionally add a basic zensical.toml at the repo root to configure site name, theme, etc. (not required for basic usage).
  8. Update README.md:
  9. Add a “Documentation” section after “Local Development” or “Deployment”.
  10. Include steps to install Zensical and run zensical serve from the repo root to preview docs at http://localhost:8000.
  11. Mention that the documentation is not deployed; it's for local reference only.
  12. Update .gitignore to ignore the generated site directory (default is docs/site/ if you build).

How to Run Locally (for README)¶

After setting up the docs: 

# Optional: create a virtual environment
python3 -m venv .venv
source .venv/bin/activate

# Install Zensical
pip install zensical

# Start the preview server
zensical serve
Then open http://localhost:8000 in your browser.

Acceptance Criteria¶

  • The /docs directory exists with the proposed structure.
  • Placeholder Markdown files are present and allow the Zensical server to start without errors.
  • The README includes clear instructions for installing Zensical and viewing the docs locally.
  • No changes are made to the existing GitHub Actions workflow (deploy.yml).
  • The documentation is not automatically deployed; it remains a local-only resource.
