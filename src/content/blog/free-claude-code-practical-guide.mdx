Free Claude Code (FCC) makes an appealing promise: keep the coding-agent workflow you already know while choosing from free-tier, paid, or locally hosted models. The important qualification is in the details. FCC is free and open-source software, but it is not free access to Anthropic's Claude models. It is a local proxy that connects supported coding agents to other model providers.

That distinction shapes how you should evaluate it. FCC can be a useful tool for learning, provider comparison, privacy-sensitive prototyping, and reducing dependence on one model vendor. Its reliability, cost, and coding ability still depend on the model and provider behind the proxy.

This guide covers a current first-run path and the trade-offs to consider before using FCC for serious work.

## What Free Claude Code Actually Does

FCC runs a local HTTP proxy between your coding agent and an upstream model provider. According to the project's [architecture documentation](https://github.com/Alishahryar1/free-claude-code/blob/main/ARCHITECTURE.md), it accepts Anthropic Messages traffic from Claude Code and Pi and OpenAI Responses traffic from Codex. It then routes each request to the configured provider and preserves the protocol expected by the calling client.

In practical terms, FCC provides:

- Launchers for Claude Code, Codex, and Pi
- A local Admin UI for credentials, models, status, and routing
- Cloud and local provider adapters
- Native model-picker integration in supported clients
- Optional routing of Fable, Opus, Sonnet, and Haiku requests to different models
- Streaming, tool use, reasoning, and image input when the selected model supports them

As of August 3, 2026, the project [documents 31 cloud and local providers](https://github.com/Alishahryar1/free-claude-code#what-you-get). That number is likely to change, so use the live provider list rather than treating 31 as a permanent limit.

## Install or Update FCC

Before piping a remote installer into a shell, review the current [macOS/Linux installer](https://github.com/Alishahryar1/free-claude-code/blob/main/scripts/install.sh) or [Windows installer](https://github.com/Alishahryar1/free-claude-code/blob/main/scripts/install.ps1). The installer manages FCC and its Python runtime through `uv`, and asks which supported coding agents it should install or verify.

On macOS or Linux:

```bash
curl -fsSL "https://raw.githubusercontent.com/Alishahryar1/free-claude-code/main/scripts/install.sh" | sh
```

On Windows PowerShell:

```powershell
& ([scriptblock]::Create((irm "https://raw.githubusercontent.com/Alishahryar1/free-claude-code/main/scripts/install.ps1")))
```

Run the same command again when you want to update FCC. Because the project moves quickly, reviewing installer changes before an update is a sensible habit.

## Start the Proxy and Open Admin

On Windows, open **Free Claude Code** from the desktop or Start menu. On macOS, open it from the desktop or Applications folder. The desktop launcher keeps FCC in the system tray or menu bar.

On Linux, or when you prefer a terminal on another platform, run:

```bash
fcc-server
```

Keep that terminal open while using FCC. Once healthy, the server logs its Admin UI address. The default is:

```text
http://127.0.0.1:8082/admin
```

Use the address printed by your server if its port differs. The Admin UI is loopback-only, so it is intended to be accessed from the same machine rather than exposed as a network control panel.

## Configure One Provider First

FCC supports commercial APIs, services with free tiers, subscriptions, and local model servers such as Ollama, LM Studio, and llama.cpp. Start with one provider and prove that the complete workflow functions before adding routing rules or fallback providers.

The upstream quick start uses NVIDIA NIM:

1. Create an API key from NVIDIA's API catalog.
2. Open the Admin UI URL shown in the FCC server log.
3. Enter the key in `NVIDIA_NIM_API_KEY`.
4. Keep the documented default model or choose another tool-capable model.
5. Select **Validate**, then **Apply**.

Other providers have different authentication and model-discovery requirements. For example, OpenAI uses a connected ChatGPT account in the Admin UI, while local providers require their model server to be running at the configured local address. Follow FCC's current [provider instructions](https://github.com/Alishahryar1/free-claude-code#choose-a-provider) instead of assuming that every provider accepts the same kind of API key.

Whichever provider you choose, prefer a model that supports tool use and has enough context for the agent's system prompt, tool definitions, conversation, and working files. A model that is good at chat is not automatically reliable at editing files or coordinating shell commands.

## Launch a Coding Agent

After the proxy is running and the provider validates, launch one of the supported clients:

```bash
fcc-claude
```

```bash
fcc-codex
```

```bash
fcc-pi
```

The launchers point each client at FCC while retaining normal CLI arguments. For example, the upstream documentation demonstrates a non-interactive Codex command:

```bash
fcc-codex exec "hello"
```

Use the client's model picker to see models exposed by FCC. If a model appears but fails during real work, test provider validation, tool calling, streaming, and context limits separately. A successful model-list request proves discovery, not full agent compatibility.

## Route Different Work to Different Models

FCC uses `MODEL` as its fallback model reference. You can optionally configure `MODEL_FABLE`, `MODEL_OPUS`, `MODEL_SONNET`, and `MODEL_HAIKU` to map Claude model tiers to different upstream models.

This can support a deliberate mix, such as:

- A stronger hosted model for complex planning
- A fast or free-tier model for routine work
- A local model for sensitive or low-risk tasks
- A fallback model when a preferred provider is unavailable

Routing is useful only when the selected models can handle the requests they receive. It does not make a small model equivalent to Opus or Sonnet; the tier name is a routing signal, not a capability guarantee. Begin with a single fallback model, collect real workflow results, and add tier overrides only when there is a clear reason.

## What Does “Free” Cost?

FCC itself is distributed under the [MIT License](https://github.com/Alishahryar1/free-claude-code/blob/main/LICENSE). It does not require an FCC subscription. Operating it can still involve several kinds of cost:

- **Provider usage:** Commercial APIs may charge by token or request. Free tiers can have quotas, rate limits, regional restrictions, or changing terms.
- **Existing subscriptions:** Connected-account providers may require an eligible subscription rather than an API key.
- **Local hardware:** Local inference uses your CPU, GPU, RAM, storage, and electricity. A model that fits is not necessarily a model that runs interactively.
- **Engineering time:** Provider setup, compatibility testing, upgrades, and troubleshooting are real operational costs.
- **Quality trade-offs:** A cheaper model can become expensive if unreliable tool use creates rework or requires constant supervision.

FCC gives you choices; it does not normalize provider billing or guarantee that a free option will remain available. Check each provider's current pricing, quota, terms, and data-handling policy before sending project data through it.

## Where FCC Fits Well

Based on my review of the available implementations and their operating trade-offs, FCC is strongest when exploration and control matter more than uniform behavior.

Good fits include:

- Learning how coding agents interact with different model backends
- Comparing models on the same non-critical repository and task set
- Prototyping under a limited budget
- Testing local models for privacy-sensitive work
- Maintaining provider options when one service is unavailable or unsuitable

Use more caution when the workflow requires predictable latency, consistently strong tool use, formal support, audit controls, or an SLA. Free-tier services can throttle unexpectedly, local models can struggle with context and tool calls, and every additional proxy/provider layer expands the troubleshooting surface.

For production or critical development, test the exact model-provider-client combination rather than evaluating FCC in the abstract. Record known-good versions and configurations, and keep a fallback that has already passed the same task-level checks.

## Security and Reliability Checklist

FCC's Admin UI is restricted to loopback access, and the proxy supports optional bearer-token authentication. Those controls are useful, but they are only part of the security picture.

Before adopting a configuration:

1. Keep the Admin UI and proxy bound to the local machine.
2. Enable proxy authentication when other local processes should not have open access.
3. Protect the FCC configuration and credential files under your user account.
4. Review each provider's data retention and training policies.
5. Test with a non-sensitive repository before sending private code.
6. Confirm tool use, streaming, cancellation, and context behavior with realistic tasks.
7. Keep a record of the FCC, client, provider, and model versions that worked.

When something fails, isolate the layers: proxy health, provider authentication, model discovery, a simple completion, streaming, and finally tool use. This is faster than changing several providers and routing rules at once.

## A Practical Starting Recommendation

Start small: install FCC, configure one provider, and run one supported agent against a disposable or non-critical repository. Choose a representative task that requires reading files, making a modest edit, and running a test. Repeat it enough times to judge consistency rather than stopping after one successful response.

If the model is reliable, add a second provider or a tier-specific route and compare the same task. If it is not, you will have a bounded configuration to troubleshoot instead of a web of fallbacks.

Free Claude Code is best understood as a portability and experimentation layer. It can reduce the friction of trying different models, including local ones, but the selected backend still determines most of the experience. The project's [README](https://github.com/Alishahryar1/free-claude-code), [issue tracker](https://github.com/Alishahryar1/free-claude-code/issues), and [discussions](https://github.com/Alishahryar1/free-claude-code/discussions) are the right places to check current compatibility before relying on a particular provider or model.
